# 🧠 LITESTATE — BASE CONCEPTUAL Y TÉCNICA (RESUMEN)

## 🎯 PROPÓSITO

Sistema web para **visualizar en tiempo real el estado operativo** de una empresa, enfocado en:

* simplicidad
* rapidez de carga
* claridad visual en monitores (TV / pantallas)

---

## 🧭 ENFOQUE PRINCIPAL

El sistema NO gestiona tareas ni órdenes complejas.

El sistema está orientado a:

> “Capturar y mostrar el estado actual de cada sector en tiempo real, con información mínima clave.”

---

## 🧱 MODELO CONCEPTUAL

### 🔹 Estado actual

* Representa qué está pasando ahora en cada sector
* 1 estado por sector
* visible en dashboards

---

### 🔹 Eventos

* Cada cambio de estado genera un registro histórico
* Permite trazabilidad y métricas futuras

---

## 🏭 ENTIDADES PRINCIPALES

* Empresa
* Usuario
* Sector
* Estado
* Evento
* EstadoActual (optimización)
* Dashboard (monitores)

---

## 👤 ROLES

### Operador

* carga estados
* asignado a un sector

### Supervisor

* visualiza información
* acceso completo

---

## 📺 MONITORES (CLAVE DEL SISTEMA)

No son usuarios tradicionales.

Se implementan como:

> “Dashboards accesibles por URL con token”

Ejemplo:

```
/monitor/{token}
```

---

## 🎯 TIPOS DE DASHBOARD

1. General (todos los sectores)
2. Por sector
3. Administrativo (más detalle)

---

## 👤 USUARIOS Y SECTORES

Un usuario puede estar asignado a uno o varios sectores.

Esto se implementa mediante una relación:

Usuario ↔ Sector (muchos a muchos)

Tabla:

UsuarioSector

* UsuarioId
* SectorId

---

## ⚡ FLUJO DEL OPERARIO (ACTUALIZADO 7/5/2026)

1. Login
2. Selecciona sector (si tiene más de uno)
3. Completa hasta 3 campos
4. Presiona estado
5. El sistema guarda automáticamente

Optimización:

* recordar último sector usado
* permitir cambio rápido de sector

Tiempo objetivo: **2–3 segundos**
---

## 🧩 CAMPOS CONFIGURABLES (DECISIÓN CLAVE)

Tipos:

* Texto corto

* Orden


### 2. GRID PRINCIPAL

Contiene tarjetas de sectores.

Cada tarjeta representa:

### Nombre del sector

Ejemplo:

```plaintext

```

Ejemplos:

```plaintext
🟢 PRODUCIENDO
🟡 ESPERANDO
🔴 DETENIDO
⚫ FINALIZADO
```

---

### Datos operativos

Ejemplo:

```plaintext

```

---

### Tiempo desde última actualización

Ejemplo:

```plaintext

```

## 🎨 COLORES DE ESTADO

### 🟢 Verde

Operando normalmente

### 🟡 Amarillo

Espera / transición

### 🔴 Rojo

Problema / detenido

### ⚫ Gris / oscuro

Finalizado

El estado FINALIZADO:

* permanece visible temporalmente
* se muestra atenuado
* tiene menor protagonismo visual

---

## ⏳ COMPORTAMIENTO DE FINALIZADOS

Cuando una operación termina:

1. el operador marca estado FINALIZADO
2. el dashboard mantiene visible el sector
3. visualmente se atenúa
4. luego de un tiempo configurable (15–30 min):

   * puede ocultarse automáticamente
   * o moverse a actividad reciente

Permitir que:

* un usuario opere varios sectores
* un sector tenga varios usuarios

---

## Relaciones

```plaintext id="u7r1wd"
Usuario ↔ UsuarioSector ↔ Sector
```

---

## Campos principales

```csharp id="s3m7fo"
UsuarioId
SectorId
```

---

# 🚦 ESTADO

Representa estados operativos configurables.

## Ejemplos

* Produciendo
* Esperando
* Problema
* Finalizado

---

## Relaciones

Estado:

* pertenece a Empresa
* tiene muchos Eventos
* puede existir en EstadoActual

---

## Campos principales

```csharp id="q1x8zr"
Id
EmpresaId
Nombre
ColorHex
Orden
Activo
EsFinalizado
```

---

# 📝 EVENTO

Representa el histórico operativo.

## Propósito

Guardar todos los cambios de estado.

---

## Filosofía

Evento:

* solo INSERT
* nunca UPDATE
* nunca DELETE lógico operativo

---

## Relaciones

Evento:

* pertenece a Empresa
* pertenece a Sector
* pertenece a Estado
* pertenece a Usuario

---

## Campos principales

```csharp id="m8t4qp"
Id
EmpresaId
SectorId
EstadoId
UsuarioId
FechaHora
```

---

## Valores operativos

```csharp id="c5n1yw"
Campo1Valor
Campo2Valor
Campo3Valor
```

---

# ⚡ ESTADOACTUAL

Tabla optimizada para dashboards.

## Propósito

Evitar consultas pesadas al histórico.

---

## Filosofía

Existe:

* un único EstadoActual por Sector

Comportamiento:

* UPDATE cuando cambia estado

---

## Relaciones

EstadoActual:

* pertenece a Sector
* pertenece a Estado
* pertenece a Usuario

---

## Campos principales

```csharp id="r4k2ye"
SectorId
EstadoId
UsuarioId
FechaHora
```

---

## Valores operativos


## Relaciones

# ⚡ OPTIMIZACIONES IMPORTANTES

## EstadoActual

Tabla física optimizada para:

* dashboards rápidos
* menos carga SQL
* hosting compartido

---

## Evento

Histórico append-only para:

* trazabilidad
* auditoría
* métricas futuras

# 🧠 DECISIONES ARQUITECTÓNICAS CLAVE
